# Beta 准入硬化设计

## 1. 目标与范围

本批次用于补齐 InsPilot 云小宝从 Alpha 进入 Beta 前的工程门槛，仅包含：

1. 关键管理操作的审计写入闭环。
2. 混合检索排序的可解释性。
3. 钉钉独立评论权限验证、评论归并和降级提示。

本批次不包含多模态输入、追问补全、Elasticsearch/OpenSearch 引入、完整审计管理后台。现有 PostgreSQL 精确召回与 pgvector 语义召回架构保持不变。

## 2. 推进顺序

按风险和依赖关系串行实施：

1. 审计闭环。
2. 检索可解释性。
3. 钉钉评论权限与降级。
4. Beta 准入回归。

审计服务先落地，因为后续配置变更和钉钉权限异常都需要可靠留痕。检索证据模型随后实现，避免钉钉回归只能观察最终答案而无法定位召回问题。评论权限验证最后接入，并复用审计与检索诊断能力。

## 3. 审计闭环

### 3.1 组件边界

新增统一审计服务，负责构造和持久化 `AuditLog`。业务路由只传入操作者、动作、资源、原因和变更摘要，不直接拼装数据库模型。

审计服务与业务变更共用 SQLAlchemy `Session`。关键操作的业务写入和审计写入必须处于同一事务：任一写入失败，整体回滚。

### 3.2 覆盖动作

- 知识：确认导入、审核状态变更、项目与敏感级别变更、删除。
- 钉钉：单条导入、批量导入。
- 项目：创建及可见性设置。
- 配置：Embedding、对话模型、生产数据库、钉钉开放平台配置修改。

### 3.3 审计字段

沿用现有 `audit_logs` 表：

- `actor_user_id`：操作者标识。
- `action`：稳定、可查询的动作代码。
- `resource_type`、`resource_id`：被操作资源。
- `reason`：用户提供或系统生成的操作原因。
- `metadata_json`：变更前后摘要、批量数量、来源类型及错误类别等非敏感上下文。
- `created_at`：服务端生成的操作时间。

API Key、AppSecret、数据库密码等秘密值不得写入审计日志。相关字段只记录是否配置、是否变更，不记录原值、新值或可逆摘要。

### 3.4 失败行为

- 关键业务写入成功但审计写入失败：整个事务失败并回滚。
- 外部测试请求失败：不回滚已保存配置；记录测试动作、目标服务和脱敏错误类别。
- 批量导入部分失败：审计记录成功数、失败数和脱敏失败原因，不记录审批正文中的敏感数据。

## 4. 检索可解释性

### 4.1 结果模型

在 `KnowledgeDocument` 之外增加检索证据对象，由检索层内部使用。证据至少包含：

- 召回渠道：`keyword`、`vector` 或两者同时命中。
- 关键词命中字段：标题、正文、来源元数据。
- 关键词召回排名。
- 向量距离和向量召回排名。
- 合并去重后的最终排名。
- 状态、项目可见性和知识敏感级别的过滤结论。

现有聊天调用保持兼容：默认仍可取得文档列表；管理端调试路径显式请求带证据的结果。

### 4.2 数据流

```text
查询
  -> PostgreSQL 标题/正文/元数据精确召回
  -> pgvector 语义召回
  -> 权限与生效状态过滤
  -> 按文档 ID 合并去重
  -> 生成检索证据和最终排名
  -> RAG 上下文 / 管理端调试展示
```

权限过滤必须发生在结果暴露给 Prompt 或管理端之前。被过滤文档的标题、正文、分数和命中字段均不得返回给无权用户。普通业务回答只展示必要来源信息，不展示向量距离等内部诊断数据。

### 4.3 管理端展示

搜索后台为每个来源展示：

- 来源类型和知识标题。
- 最终排名。
- 召回渠道。
- 命中字段。
- 关键词排名和向量排名；未参与的渠道显示为空。

Prompt 继续负责根据已召回上下文组织答案，不承担记录召回或排序职责。

### 4.4 固定回归样本

使用审批号 `202605281923000432811` 对应知识作为固定样本。以下查询中，该知识必须进入 Top 8：

- `西宁市`
- `浙江华重融资担保`
- `华重担保`
- `202605281923000432811`

每个结果必须能解释召回渠道和命中字段。机构名称存在多条相关审批时，不要求目标记录固定排第一。

## 5. 钉钉评论权限与降级

### 5.1 数据来源

评论信息由两个来源组成：

1. 独立评论接口 `dingtalk.oapi.processinstance.comment.list`，提供评论内容、评论人和时间。
2. 审批实例操作记录，提供节点、操作人、操作意见和时间，作为稳定降级来源。

两类记录转换为统一内部结构，再依据稳定字段去重。去重键优先使用平台记录 ID；缺少 ID 时使用来源、人员、时间和规范化内容组合。

### 5.2 权限检测

钉钉配置测试分别返回：

- 基础连接与 access token 状态。
- 审批详情读取权限状态。
- 独立评论读取权限状态。

三项必须独立展示，不能以基础连接成功替代评论权限验证。

### 5.3 降级语义

- 独立评论接口无权限或不可用：审批预览和导入继续执行，使用操作记录，并显示明确降级提示。
- 独立评论接口临时异常：记录脱敏错误类别和降级结果，不静默吞错。
- 两个来源均无评论：显示“未获取到审批意见”，不得伪造空评论或将其表述为接口成功。
- 独立评论与操作记录重复：知识正文只保留一条，并保留完整节点信息。

## 6. 测试策略

采用 TDD，按三个可独立提交的工作包实施：

1. 审计服务及关键操作接入。
2. 检索证据模型、混合召回排序和后台展示。
3. 钉钉评论权限检测、归并和降级提示。

测试覆盖：

- 审计成功、事务回滚、批量摘要和秘密字段脱敏。
- 关键词单渠道、向量单渠道、双渠道合并、去重、最终排名。
- 未授权知识不会通过调试证据泄露。
- 独立评论成功、无权限、临时异常、去重和无评论场景。
- 管理端配置测试和搜索解释信息的响应契约。
- 真实工单预览、导入和四个固定查询的人工回归。

## 7. Beta 准入标准

以下条件必须全部满足：

- 全量 `pytest` 通过。
- Ruff 检查通过。
- `git diff --check` 通过。
- 密钥、AppSecret、数据库密码不进入审计日志。
- 权限受限知识不通过检索调试信息泄露。
- 四个固定查询均在 Top 8 召回目标审批，并提供召回解释。
- 工单 `202605281923000432811` 的预览、导入和检索链路回归通过。
- 评论接口无权限时，审批操作记录仍完整导入，后台明确展示降级状态。
- 不引入 Elasticsearch/OpenSearch，不扩展到多模态和追问补全。
